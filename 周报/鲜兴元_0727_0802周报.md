# 鲜兴元 2026.07.27-2026.08.02 周报

## 一、本周工作内容

本周主要围绕 Spider2 的 Agent 系统开发展开，工作集中在 `methods/spider-agent-tc` 目录下。重点完成了 Agent 框架的 LangGraph 改造、主 Agent 工具链的重新设计、Schema Router 表压缩模块的开发与全量评测，以及 Router 接入主 Agent 后的端到端验证。主要包括以下四个方面：

1. 完成 Agent 框架的 LangGraph 改造，搭建自动评分与实验管理基础设施。
2. 重新设计主 Agent 工具链，将原有单一 SQL 执行工具拆分为结构化多工具体系，准确率从 52.08% 提升至 63.27%。
3. 开发 Schema Router 表压缩模块并完成 120 题全量评测，物理表 Micro Recall 达到 97.78%，平均压缩率 70.03%。

### 1. LangGraph 框架改造与实验基础设施建设

本周首先对 Agent 框架进行了 LangGraph 改造，将原有的线性对话循环重构为基于状态图的 Agent 工作流，使工具调用、结果回传和轮次控制更加清晰。同时完成了以下基础设施搭建：

* 自动评分模块：每次运行结束后自动对比 Gold SQL 结果，生成 REPORT.md 报告。
* 实验管理：一个 YAML 配置文件对应一组运行结果，结果目录以时间戳自动命名，支持断点续跑。
* 运行监控：控制台精简输出、显示实时时间与推理速度、动态写入日志文件。
* 工具并发执行：支持同一轮次内多个工具调用并发执行，减少等待时间。

### 2. 主 Agent 工具链重新设计

在框架改造完成后，对主 Agent 的工具链进行了重新设计。原有方案仅提供 `execute_snowflake_sql` 和 `execute_bash` 两个通用工具，Agent 需要自行探索数据库结构，效率较低且容易出错。新方案将工具链拆分为 9 个结构化工具：`search_schema`（模式搜索）、`describe_table`（表结构描述）、`resolve_table_set`（表集合解析）、`execute_sql`（SQL 执行）、`build_union_sql`（联合查询构建）、`get_sql_text`（SQL 文本获取）、`get_task_context`（任务上下文获取）、`read_query_result`（结果读取）和 `terminate`（终止提交）。

同时在初始 Prompt 中加入了所有数据库的 Schema 概览信息，并更新了引导策略。修改前后在同一组 50 题上进行了对比实验：

| 指标           | 修改前（0729）  | 修改后（0730）  | 变化量          |
| -------------- | --------------- | --------------- | --------------- |
| 任务成功率     | 96.00%（48/50） | 98.00%（49/50） | +2.00%（+1）    |
| 准确率         | 52.08%（25/48） | 63.27%（31/49） | +11.19%（+6）   |
| 全数据集得分率 | 4.57%（25/547） | 5.67%（31/547） | +1.10%（+6）    |
| 平均对话轮次   | 26.1            | 25.3            | -0.8            |

> 备注：Snow数据集总共有500+题目，我们从500题随机抽取50个题，并固定该50题作为开发集。先在这50题上测试改进效果。

工具链改造后，Agent 不再需要大量 bash 探索（原占比 30%），转而使用结构化 schema 工具主动获取表信息，SQL 执行效率和结果正确率均有明显提升。

### 3. Schema Router 表压缩模块

本周还开发了 Schema Router 模块，用于在 Agent 正式推理前对大规模数据库进行表级压缩，减少 Agent 需要处理的 Schema 信息量。Router 根据任务问题语义，从数据库的全量物理表中筛选出与任务相关的候选表集合，并按 required / supporting / possible 三级置信度分层输出。

在 120 道官方给出标准答案 SQL 题目上完成了全量评测，主要结果如下：

| 指标                | 结果   |
| ------------------- | ------ |
| 物理表题级全覆盖率  | 94.17% |
| 物理表 Micro Recall | 97.78% |
| 物理表 Macro Recall | 97.73% |
| 平均物理表压缩率    | 70.03% |
| 平均表族压缩率      | 67.91% |
| Recall@5            | 96.18% |
| Recall@10           | 97.73% |

当前针对表压缩效果较好，大多数题目能够从几十张甚至上百张表筛选出低于10张的有效表。大幅减少了后续主agent的探索范围。

评测中 120 题全部完成，无失败 Rollout。113/120 题实现了物理表全覆盖，7 题存在部分遗漏。具体详细的压缩结果参考附件。

## 二、本周学习内容与收获

本周最大的收获是理解了 Agent 工具设计对最终效果的显著影响。在模型和 Prompt 基本不变的情况下，仅通过将通用工具拆分为语义明确的结构化工具，准确率就提升了约 11 个百分点。这说明对于 Text-to-SQL 类任务，降低 Agent 每一步的决策难度比增加模型能力更为关键。Agent 不需要"什么都能做"的万能工具，而是需要在正确的时机获得正确的信息。

在 Schema Router 的开发中，进一步认识到大规模数据库（如 CENSUS_BUREAU_ACS_2 有 296 张表、TCGA_MITELMAN 有 176 张表）直接将全量 Schema 塞入上下文是不可行的。表压缩不仅是性能优化，更是让 Agent 能够聚焦于正确表集合的必要前置步骤。70% 的平均压缩率意味着 Agent 只需处理原来不到三分之一的表，同时 97.78% 的召回率保证了信息损失极小。

1. Schema Router 当前版本存在 75 次非法/越权引用尝试，虽然不影响召回率，但说明 Router 在边界约束上还需加强。
